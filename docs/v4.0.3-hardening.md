# DirFuzz v4.0.3 — Intelligence Correctness & Security Hardening

This is a corrective milestone, not a new-feature release. It is intended to retain the existing scanning workflow while making the analyst-intelligence and MCP boundaries more dependable.

## Changes in this branch

- Preserve the sign of rejected/dismissed knowledge weights. Use a true exponential half-life for positive and negative evidence; do not convert zero or negative evidence into a positive boost.
- Persist the campaign identifier on recorded campaign-scoped decisions, so lookups match the intended campaign only.
- Compare actual endpoint status, size, content type, and body hash in addition to risk score. Treat 401/403 to 2xx as a critical candidate auth-boundary regression to validate, not proof of a vulnerability.
- Fingerprint changed endpoint transitions using all evidence fields instead of only risk score, preventing unrelated changes from sharing a diff-memory key.
- Record only allowlisted MCP argument names and non-string scalar metadata in audit logs. Do not persist raw headers, request bodies, URLs, auth matrices, or unknown argument contents.
- Bind follow-on probe destinations to the original HTTP scheme, hostname, and effective port. Validate expansion destinations before starting their subscans.
- Correct source build instructions and clarify that complete durable campaign-ledger replay remains future work.

## Regression gates

The repository CI runs:

```bash
go test ./... -timeout=8m
go vet ./...
go test -race ./pkg/engine ./pkg/httpclient -timeout=10m
go test -race ./pkg/knowledge ./pkg/campaign ./cmd/mcp -timeout=10m
```

The v4.0.3-specific tests cover rejected evidence, true half-life behavior, campaign isolation, stable-risk structural diffs, fingerprint uniqueness, audit redaction, and follow-on origin binding.

## Validation still required before tagging

- Confirm all CI jobs are green on the pull request and review any test failures.
- Run the compiled Windows, Linux, and macOS release binaries in smoke tests where available.
- Test bounded scans on an authorized local HTTP lab with 401/403-to-200 transitions, noisy 200 pages, redirects, and cancellation.
- Verify redirect-chain scope enforcement and real-world false-positive rates separately; matching an initial destination does not establish that every subsequent redirect is authorized.
- Confirm that full typed-event campaign persistence/recovery is not claimed as shipped. The current append-mode JSONL history and supported TUI sidecar are separate from the campaign EventStore abstraction.

Do not tag v4.0.3 until the gates above are checked. No new autonomous scanning, new integrations, or new campaign features are part of this milestone.
